ToolVeto Documentation

ToolVeto is the deterministic chaos testing, CI blocking gate, and runtime airbag platform for Model Context Protocol (MCP) servers.

CLI Quickstart

Evaluate any local server directory, binary script, JSON schema manifest, or live Streamable HTTP endpoint in under 90 seconds with zero LLM API costs:

# Audit a local MCP server directory npx toolveto@latest check ./my-mcp-server # Audit a static tool schema JSON npx toolveto@latest check ./schema.json # Audit a live remote Streamable HTTP MCP server npx toolveto@latest check http://localhost:8080/mcp # Automatically patch local source files for failed checks npx toolveto@latest fix --apply

The 5 Behavioral Dimensions

ToolVeto tests MCP servers against the exact failure modes discovered in production agent operations:

D1 Idempotency & Concurrency (Weight: 30%)

When an LLM agent times out or receives a transient network error, it immediately replays the tool call. Without explicit idempotency keys and atomic backend deduplication, this leads to double-charges and duplicated database records.

  • TC-IDEMP-001: Sequential Replay Veto — Executes mutations 5× with identical inputs and asserts zero duplicate records.
  • TC-IDEMP-002: Concurrent Thundering Herd — Fires N=10 simultaneous requests within Δt < 20ms.
  • TC-IDEMP-003: Schema Idempotency Declaration — Asserts presence of idempotency_key or client_request_id in the input schema.

D2 LLM Self-Correction & Error Feedback (Weight: 25%)

Opaque 500 errors and raw stack traces trigger recursive 47× retry spirals in frontier LLMs. Errors must cite the exact failing parameter and provide concrete formatting examples.

  • TC-FUZZ-001: Type Inversion Fuzzing — Injects NaN, objects, and empty arrays; asserts isError: true without crashing the server.
  • TC-FUZZ-002: Hallucinated Parameter Guard — Injects parameters imagined by models (e.g. force: true) to ensure additionalProperties: false is enforced.
  • TC-ERR-001: Error Self-Healing — Tests invalid formats (e.g. "tomorrow morning" for dates) and verifies error citations.

D3 Context & Token Hygiene (Weight: 25%)

Unbounded collection queries dump tens of thousands of tokens into the context window, degrading model attention and triggering fatal out-of-context errors.

  • TC-CTX-001: Context Bomb Veto — Flags responses > 8,000 tokens as VETO_DATALOSS.
  • TC-SCHEMA-001: Collection Pagination — Verifies limit and cursor exist on all list queries.
  • TC-SCHEMA-002: Description Clarity — Flags descriptions under 30 characters as too terse for reliable model routing.

D5 State Auditability & Pairing (Weight: 10%)

Blind-write mutations prevent agents from inspecting existing state before writing or verifying state after mutating.

  • TC-PAIR-001: Read-Before-Write Pairing — Requires mutating tools (e.g. charge_customer) to have companion read queries (e.g. get_customer).
  • TC-DRYRUN-001: Dry-Run Simulation — Ensures destructive mutations support preview execution.

GitHub Actions CI Blocking Gate

Add ToolVeto to your repository to automatically block PRs with critical agent vulnerabilities:

# .github/workflows/toolveto.yml name: ToolVeto Gate on: [pull_request, push] jobs: audit: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: 20 - name: Run ToolVeto Reliability Gate run: npx --yes toolveto@latest check .

Runtime Airbag: @toolveto/shield

For third-party servers you cannot modify upstream, wrap your MCP server in @toolveto/shield:

import { shield } from '@toolveto/shield'; import { RedisShieldStorage } from '@toolveto/shield/stores/redis'; export default shield(myMcpServer, { idempotency: true, loopLimit: { count: 5, windowMs: 30000 }, tokenBudget: 4000, storage: new RedisShieldStorage(redisClient), });

CISO Evidence Packets & AIUC-1 Compliance

Generate RFC 7515 JWS cryptographically signed evidence packets for enterprise security reviews:

# Generate terminal compliance report npx toolveto evidence --format aiuc1 # Export machine-readable JSON packet with JWS token npx toolveto evidence --format json --output evidence.json
