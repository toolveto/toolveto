1. Executive Summary: The Agentic Reliability Crisis

The Model Context Protocol (MCP) is rapidly becoming the universal open standard for connecting large language model (LLM) agents to external data sources, business APIs, and tools. However, 98.7% of existing MCP implementations were written as simple wraps around existing REST APIs, built on the fatal assumption that callers are disciplined, human-driven web clients.

When autonomous agents (e.g. Claude Sonnet 4.6, GPT-5.4, Gemini 3.1 Pro) operate these tools in production loops, they exhibit distinct operational failure modes:

  1. Retry Storms on Latency: When an API call exceeds a 3-second timeout, agents retry blindly. Without explicit idempotency keys, mutating calls result in duplicate payments, double tickets, and orphan databases.
  2. Context Window Eviction: Unbounded list queries dump hundreds of kilobytes of unpaginated JSON into the prompt, obliterating prior reasoning instructions and degrading agent accuracy.
  3. Blind Mutations: Write operations lack companion inspection queries, leaving agents unable to verify whether an action succeeded or corrupted state.

Stripe Agent Toolkit (stripe/agent-toolkit)

Bronze (63/100) CI: BLOCKED (6 Crit)

Primary Finding: The create_payment_intent and refund_charge tools accept payment amounts and customer IDs but expose no idempotency_key parameter. When an agent experiences socket latency, retrying the mutation creates multiple duplicate payment intents.

GitHub Official MCP Server (github/github-mcp-server)

4. Evaluation Methodology & Scope

Responsible External Scope: In strict compliance with security standards, all third-party external repositories in this benchmark were evaluated exclusively using Stages 1 and 2 (Schema Introspection & Static Contract Verification). Zero live mutation probes or burst calls were sent to live infrastructure.

The ToolVeto static checker parses the declared tool signatures and evaluates them against 12 core reliability invariants:

  • TC-IDEMP-003: Presence of client-controlled idempotency tokens on mutating tools.
  • TC-PAIR-001: Mandatory pairing of write tools with corresponding read inspection tools.
  • TC-CTX-001: Enforced pagination bounds on all collection and query tools.
  • TC-SCHEMA-001 / 002: Strict field descriptions and strongly-typed parameter constraints.

5. Responsible Disclosure Protocol

ToolVeto follows a strict, constructive open-source remediation model:

  • Fix-First Policy: We never publicly critique a tool schema without providing an active, tested GitHub Pull Request containing the exact solution.
  • Zero Exploit Vectors: Public schema ergonomics and parameter typing carries zero PII or private exploit risk.
  • Maintainer Collaboration: Maintainers of audited repositories are invited to merge the ready-made PRs or integrate the ToolVeto GitHub Action for continuous verification.
